# CTF Challenge Playbook · Agent Skill

<p align="center">
  <b>一个可以直接装进 AI 编程助手的 CTF 作战 skill</b><br/>
  <sub>skill name <code>ctf-challenge-playbook</code> · 触发词：开始比赛 / 开始解题 / 交 flag / 写 WP / 复盘比赛</sub>
</p>

**一套打 CTF 时真正会照着做的作战手册** —— 不是题解合集，是「开赛前该读什么、解题时先做什么、什么时候必须停手、赛后怎么交付」的流程与判据。

> A field-tested playbook for CTF competitions: pre-match discipline, in-match triage, evidence handling, budget control, and writeup delivery. Written in Chinese; structure and sections are self-explanatory for non-Chinese readers.

---

## 这个仓库解决什么问题

打 CTF 最容易输的地方，从来不是"不会那道题"。是这些：

- 开赛前没读本场红线与 AI 规则，套用上一场的规矩 → **违规**
- 解出来了但 flag 口径猜错，交了 17 次全被拒 → 假设空间没缩小，只是在横向乱试
- 三个候选全被否掉后继续盲目枚举 → 手里的信息没有变成约束
- 同时开 16 个会话、烧掉 10 亿 token、主控 14 分钟就停摆 → **没有预算闸门**
- 比赛结束才发现 WP 没写、台账没回填、交付格式不对 → 分数到手，沉没

本手册把上述每一条都写成了**可执行的检查项、判据和收口条件**，并在正文里附上真实赛场的数字作为参照（哪个数是真的、哪个数只是标定，都标了）。

**阅读方式**：`SKILL.md` 是唯一入口，正文按需取。不要一次读完 `refs/` —— 这份手册的第一条设计原则就是"全量加载会拖垮上下文"。

## 怎么用

**作为 AI 编程助手的 skill**：把整个目录放进你的 skills 根目录（例如 `~/.agents/skills/` 或项目内 `.dsh/skills/`），`SKILL.md` 的 frontmatter 会被识别为技能描述，之后说"开始比赛 / 开始解题 / 写 WP"即可触发。

**作为人读的手册**：直接读 `SKILL.md`，再按 `refs/CATALOG.txt` 找你需要的章节。所有章节都是纯 Markdown，不依赖任何工具。

**重新生成索引**（改了 refs 之后）：

```bash
python tools/gen_catalog.py
```

## 设计原则

1. **入口单页，正文分片** —— 入口只放闸门与路由，细节全部下沉到 `refs/`，按需加载。
2. **判据只认回执** —— flag 是否解出、状态是否成立，以平台回执为准；会话自述、自查清单通过都不算。
3. **被否的候选是约束** —— 每被拒一条，必须写下一句"这否定了哪个假设"，据此做减法，而不是继续横向枚举。
4. **先写预算再开赛** —— 并发上限、token 上限、收口条件在开赛前写死，赛中只执行。
5. **数字要标定来源** —— 手册里的实测数字都标明是一次具体比赛的观测，不是普适常量。

## 仓库边界

本仓库**只包含方法论与判据**，不包含：

- 私有语料库（历年 WP 原文、漏洞长文、现成脚本集合）
- 任何赛事 flag、题目的解题脚本、平台凭据
- 任何真实目标的地址、凭据、内部资料

正文中出现的赛事名称、平台域名只用于说明**赛制差异**，不构成对该平台的任何授权或背书。
