## 家族 1 · Mosaic / Carrier 筛选类（385 / 390 同模板）

### 指纹

| 附件 | 说明 |
|---|---|
| `carrier.bin` | 16 × `0x200`（512 B/页），**内容全随机** |
| `carrier_map.png` | 规格图，**信息全在这张图里**（记录布局、判据、表都在图上） |

### 记录布局（定长页，偏移全部相对页首）

| 偏移 | 字段 |
|---|---|
| `+000..+01F` | masked share |
| `+1E0` | `id` |
| `+1E2` | `status` |
| `+1E4` | `CRC32`（**大端**，覆盖 `+000..+1DF`） |
| `+1EC` | `reserved` |

### 主干

1. 筛页：**四条判据同时成立**才算参与页 —— `status==0x5A`、`reserved==0xA5`、CRC 匹配、`id ∈ mosaic table`。
2. 解掩：`share = page[0:32] ^ mask_for(page_id, order)`。
3. 5 个解掩份额**逐字节异或**。
4. 再按题面口径算 flag 摘要（见下"flag 口径"）。

### 陷阱

- **诱饵页可以让前三条全过**：390 的 `P10` / `id 2A` 就是只差"不在表里"。
- **16 页 CRC32 往往全部自洽** ⇒ CRC 只是完整性校验，**不是筛子**；真正有筛选力的只有 `id ∈ table`。
- **flag 口径不能猜**：385 上 `sha256(secret)` 的原始字节 / 小写 hex / 大写 hex / `前16_后16`、以及位序备选（左列=bit0、行倒读、列主序）**全部被平台拒**（共 17+ 条）；390 台账里 `sha256(secret 大写hex文本)` 同样**已被拒**。
- **拿到这种题先确认题面里有没有定义 `canonical`**；没定义说明还没找对材料，**不要靠枚举拼写/分隔符去撞**（385 就是这么白烧 17+ 次提交的）。

### 已锁死的中间量与未解卡点

| 项 | 值 |
|---|---|
| 390 已确认参与页（`id, order`） | `P01(21,1)` / `P04(24,2)` / `P07(27,3)` / `P11(2B,4)` / `P14(2E,5)` |
| 390 FAMILY | `MOSAIC-CARRIER-7` |
| 385 有效碎片 | `01(A17)` / `03(C09)` / `05(F31)` |
| 385 signing secret | `[REDACTED]` |
| 390 未定（下次优先攻） | `mask_for` 里 `page_id`/`order` 的**宽度编码**（1 字节 vs `uint16be`）；`[0:32]` 切 `digest` 还是 `hexdigest`；`canonical` 未定义 |

### flag 口径（本题族实测，官方提示原文）

```
flag = sha256(canonical.encode() + manifest_secret).hexdigest()
```

即**先把一个 canonical 字符串与恢复出的原始字节拼起来，再 sha256**，不是对 secret 单独 hash。
对 385 的同构写法，`canonical` 应取 canonical tenant（note 里说的"签名材料"）。
**没定义 `canonical` 就直接问出题人，别猜。**（flag 口径总表 → `04-flag-and-ledger.md`）

### 自证判据

- 四判据必须**同时**成立，且只能靠 `id ∈ table` 区分诱饵 —— 若你筛出的页数 ≠ 表内条目数，就是筛错了。
- 5 个份额异或后应得到**语义可读**的摘要材料；若不可读，先怀疑 `mask_for` 的宽度编码与切法（上表卡点），别改判据。

## 家族 2 · 差分 / 补丁链类（391 Delta Forge，已判正）

### 指纹

| 附件 | 说明 |
|---|---|
| `base_image.bin` | 不可变基线，**整片随机** |
| `ecu_delta_container.bin` | 只有几百字节 |
| `*_protocol.txt` | 协议说明（**注意：里面写的定义可能是错的，见陷阱**） |
| `calibration_stamp.txt` | `FAMILY` / `ROOT ID` / 序列范围 / 目标偏移 |

### 主干

1. **容器解帧**：`uint16 BE 长度 || payload` 循环切，游标读到文件末尾不剩 ⇒ 帧结构确认。
   实测：301 B 切出 **20 条**，长度 **10~17 B**。
2. **解密**：`keystream = SHA256(FAMILY || parent_id || uint16be(S))` 重复异或；
   `parent_id` 初值 = 标定戳的 `ROOT ID`。
3. **明文补丁布局**：

   | 偏移 | 字段 |
   |---|---|
   | `+00` | `EC 4F` magic |
   | `+02` | `offset` u16BE |
   | `+04` | `op` u8 |
   | `+05` | `length` u8 |
   | `+06` | `data[len]` |
   | `+06+len` | chain hint u16BE |
   | `+08+len` | checksum u8 |

   op 取值：`A0` 覆写 / `A1` 异或 / `A2` 加 mod256 / `A3` 按 data 循环左移 `data%8` 位。
4. **链式摘要是唯一判据（本题题眼）**：
   `digest = SHA256(FAMILY || image_after_patch || uint16be(S))`，
   要求 `hint == digest[0:2]`，且 `next parent_id = digest[0:8]`。
   hint 依赖**打完补丁后的整张镜像** ⇒ 16 位碰撞 1/65536，**诱饵记录伪造不出来**。
5. **选记录不能靠位置/顺序**：对每个 S 把**全部**记录都试一遍，同时要求
   magic + 长度自洽 + 校验和 + hint 命中，**唯一通过者为真**。实测 20 条 → **12 真 8 诱饵**。
6. **manifest**：`MANIFEST_KEY = SHA256(FAMILY || base_image[0:manifest_off] || uint16be(S_final) || "MANIFEST")`，
   重复密钥异或后剥掉尾部填充（本题填充字节 `0xA5`）。

### 陷阱（同类题必查）

- **协议文档里的校验和定义可以是错的/是诱饵**：文档写 "XOR of every prior plaintext byte"，
  但按 XOR 一条都过不了；**实际是 SUM mod 256**。
  判据要用"**能同时解释多个独立字段**"的那个假设：本题 SUM 同时解释了 stored byte
  （`sum(ec..a7)&0xFF = 0x24` 命中）**和** 16 位 hint（依赖整镜像，不可能巧合）。
- **序列基准可以是 1 不是 0**：`ROOT SEQUENCE 0000` 指**根状态**而非第一帧；
  用 `S=0` 解 20 条全败，`S=1` 才出第一条。**起手把 S=0/1 各试一遍。**

### 自证判据（交付前必做）

1. **独立复核**：重放完的镜像与基线**逐字节 diff**，差异应是**若干段连续区间**，
   每段的 `(起点, 长度)` 与链表里对应补丁的 `offset/len` **一一吻合**（本题 **12 段 / 39 字节**）。
2. 再**全附件搜 `GEELY{`**（或本题 flag 前缀）确认**没有埋诱饵 flag** —— 本题全库唯一命中即解出的那条。

## 家族 3 · CAN 状态推进类（389 Pressure Gate / 386 CAN Noir 同模板）

### 指纹

题面给「一段总线记录 + 命中拒绝帧（**不推进状态**）+ 预测下一帧完整数据」，
再要求 `GEELY{<前缀>_<hash前16位>_<hash后16位>}`。

### 主干

1. **先把参数出处拆清**：这类题会把参数**分散到不同介质**——
   算法在一张「诊断公告」图里、`ROT`/`MASK` 在**磁带音频**里、`MULT` 在**旋钮照片**里、`SBOX` 在**色环照片**里。
   先列出"哪个参数来自哪份附件"，再逐个解。
2. **音频/磁带类（FSK）**：卡面通常直接给调制方式（如 `Mark=1800 Hz` / `Space=900 Hz`、`45 ms/bit`、MSB first、同步字 `A5 C3`）与 CRC 定义。
   解完**必须用卡面给的 CRC 复算一遍**（389 复算得 `0x3A44` = 解出的 crc16 ⇒ **位对齐 + 字节序双证**）。
3. **旋钮/表盘类**：数值在**指针角度**里（红色指针像素取**远端**求方向，**质心会被锥形刀身带偏**）；盘下印的数字常是量程。
4. **色环/色卡类**：是**双层映射**——环上印的 `0..F` 是序号，真正的替换表 = **盘色 → 底部图例标签**。
5. **过滤判据只有一个字段**（389 = `status==0x5A`）；帧内 XOR 校验和**往往全帧自洽、不是筛子**。
6. **自证**：用解出的参数复算所有有效帧之间的状态转移，**全中才算解出**（389 = **71/71**）。
7. **下一帧 counter**：先量时间戳间隔（389 全 **96 帧 ~60 ms 一发** = 连续抓包）⇒ 立即排除"计数器按帧递增"，
   拒绝帧的 counter 是**伪造值**；下一帧 counter = 上一条**有效**帧 + 1。
8. **flag**：`sha256(<下一帧的大写 hex 文本>)` 取前 16 + 后 16、**小写**。

### 陷阱

- **不该铺候选 flag**：口径拿不准时应先找"同族标定样本"（393/395/396 的 protocol 文件 + 386 参考 flag）把约定钉死，
  再算唯一解；当年摊了 **9 条候选**，被用户当场纠正"不要再猜了"。
- **对齐口径的时机太晚**：应在拿到题面（分诊阶段）就先确认 flag 口径，而不是被判错后才回头。
- flag 哈希输入取**大写 hex 文本**而非原始字节，实测（平台判正）：
  `sha256("<答案大写 hex 文本>")` 取前16/后16 ✅；而 `sha256(bytes.fromhex("<同一答案>"))` ❌
  （口径总表 → `04-flag-and-ledger.md`）。

### 自证判据

- **参数链的双证**：音频解出的 crc16 与卡面给的 CRC 定义复算值相同；色环/SBOX 解出的表能对全部样本帧自洽。
- **转移全覆盖**：解出的参数必须能复算**每一对**有效帧的状态转移（71/71），差一条就说明参数还没解全。
- counter 结论必须由**时间戳间隔**支撑（连续 vs 有间隙），不能靠猜。

## 家族 4 · 车云「未签名头重绑定」类（395 TSP Shadow Rebinding，已判正）

### 指纹

| 附件 | 说明 |
|---|---|
| `*_envelope_profile.txt` | 信封/受理规则/CODE 公式 |
| `tsp_vehicle_signer_public.pem` | 固定 **P-256** 公钥 |
| `policy_epochs.json` | 平台 `epoch` / `vehicle.version` |
| `mqtt_shadow_trace.jsonl` | 若干条 `header_b64` + `protected_payload_b64` + `signature_p256_raw_hex` + `wire_signature_valid` |

### 主干

1. **先分清哪段被签名**：profile 明写 `policy_epoch` / `merge_mode` 在 **unprotected header**、
   **不在签名覆盖范围**；`payload` 按收到的字节精确签名 ⇒ **重绑定 = 改 header、载荷与签名原样不动**。
2. **挑 victim 要把判据写全**（三条缺一不可）：
   ① 签名**有效** —— 用公钥**逐条验签**，**别信 `wire_signature_valid` 字段**；
   ② `payload.vin` 与 MQTT topic 的 VIN **一致**（跨 VIN 重放会被绑定挡掉）；
   ③ 载荷语义必须是题目要的那个动作（如 `remote_cmd="unlock"` + `maintenance_mode=true` + `operator_scope="factory"`）。
   实测 7 帧里：`209` 形态最完美但 `wire_signature_valid=false`（**诱饵**）、`202` 是跨 VIN、
   `288`/`331` 无 unlock ⇒ **唯一可用 = 188**。
3. **重绑定后逐条对受理条件**（epoch 等于平台世代 / merge_mode 用保留的旧模式 / 版本回退由该模式正当化），
   把每条结论写进 WP —— 这就是"能通过受理"的证明链。
4. **CODE 公式照抄题面**：
   `SHA256(SHA256(DER(SPKI)) || SHA256(原始载荷字节) || SHA256(新 header 字节) || ASCII(tag))`；
   取**前 24 / 后 24** 小写 hex 填进 `GEELY{TSP_<前24>_<后24>}`。
   哈希输入的"新 header 字节"用**紧凑 JSON 的原始字节**（与 trace 里所有 header 同格式），**不是 base64 文本**。

### 陷阱

- **题面规则互斥时，正确动作是找第三条证据把口径定死**，不是列"两种读法"当备选按顺序试。
  本次 `payload.version >= 250` 与 unlock 帧版本最高 `243` 互斥；实际 grader 判正的是 **frame 188（v241）**：
  `>= 250` 那条是对**当前状态帧**的规则，"original signed payload" = 唯一签名有效且 VIN 匹配的真影子，两者不冲突。
- **本机环境坑（复现时先绕开）**：`<TOOLS_DIR>\Lib` 下有 `dataclasses.py`/`inspect.py` **影子模块**，
  会让 `cryptography` 的 serialization 导入链在 `pub.verify()` 处报
  `TypeError: missing 1 required positional argument: 'signature_algorithm'`
  ⇒ 题目脚本改用**纯标准库手写 P-256 验签**；另外脚本**别命名为 `inspect.py`**（会遮蔽标准库）。

### 自证判据

- **提交前先查 `solved`**（多会话并行队伍），**验证通过立刻交**，绝不攒到最后。
- **一题一答案**；写不出「判据 → 唯一解」就**不提交**。
- 唯一性证明 = 三条判据逐条排除其余帧（本次：7 帧排除 6 帧，只留 188）——把排除过程写进 WP。

## 家族 5 · DoIP/UDS 动态环境题现场手册（399 Gateway Dual Channel，通道已打通）

### 协议骨架（同类题直接照这个顺序打）

| 步骤 | 帧 / 值 | 说明 |
|---|---|---|
| 帧格式 | `02 FD <type:2 BE> <len:4 BE> <payload>` | 未知 type 一律回 `0x0000` + 1 字节码 |
| ① 识别 | `02 FD 00 01 00 00 00 00` → `0x0004` = `VIN(17) + 逻辑地址(2) + EID(6)` | **地址线索全在这**：`LA=0x0E00`、EID 前 2 字节 `0E 80` |
| ② 路由激活 | `0x0005`，载荷 `SA(2)+type(1)+尾部` → `0x0006` = `SA(2)+LA(2)+状态(1)` | 本题只有 `SA=0x0E80, type=0x00` 被接受（回 `0x10`），其余回 `0x07` |
| ③ 诊断 | `0x8001`，载荷 `SA(2)+TA(2)+UDS` | 本题必须 `SA=0x0E00 → TA=0x0E80`，否则回 `0x8003` NACK（`SA TA 02`） |
| ④ 会话/读 DID | `10 03` → `50 03 00 32 01 F4`；`22 F187` → 12 字节票据 | 未开会话读 → NRC `0x33`；不支持的服务回 NRC `0x11` |

### 两条方法论（比上面的具体值更重要）

1. **地址从设备自报的标识符派生**：识别响应里的 `LA`/`EID` 就是候选地址来源
   （`0x0E80` 就藏在 EID 前两字节 `0E 80` 里），**不要先套 ISO 默认的 `0x1000`**。
   "设备自报的东西"优先级高于"标准默认值"。
2. **单字段差分扫描**：所有输入回同一个码时，**固定其余字段只变一个字节**，
   找"能改变回显"的位置（399 上 `idx=1` 取 `0x80` 是唯一非 `0x07` 的取值，一击命中 `SA=0x0E80`，15 秒破 5 轮僵局）。
   比对必须用**语义签名**（错误响应只看错误码、成功响应看内容），否则 NACK 原样回显 `SA TA`
   会让**每个组合都显示"与基线不同"** = 纯假信号。

### 陷阱 / 未解卡点（下次优先攻）

- 题面说"两条通道"，第二条（SOME/IP 标定服务）在题目给的**单一端口**上**没有任何可达封装**
  （裸 SOME/IP / SD / 长度前缀 / 内嵌 DoIP / UDP 全试过）。
  ⇒ **下次遇到"多通道/多服务"题，第一件事是向用户确认平台暴露了几个入口/端口**（人类 1 分钟动作），
  不要自己在同一端口里盲找第二个协议族。
- 票据 12 B `AB2C1519D0DB79C8333F60C4` 与 **434 个**朴素哈希候选
  （sha1/256/384/512、md5、HMAC、截断）**全不匹配** ⇒ **不是朴素哈希**，应按"加密块 / 带密钥 token"处理。
  （"不是朴素哈希"这个结论本身就是重要情报。）

### 自证判据

- 帧结构正确性：**游标读到文件/流末尾不剩**（同家族 2 的 `uint16 BE 长度` 切分法）。
- 地址正确性：差分扫描出的取值必须是**唯一非默认回显**的那个，且能通过后续步骤（路由激活 → 诊断）验证。
- 工具化：`zeekr-2026\tools\doip_uds.py`（`discover` / `fieldsweep` 子命令）+ 离线练习靶机 `zeekr-2026\tools\mock_doip.py`。

## 指针：385 的两条最贵教训（已在"错误模式清单"里，此处不重复）

| 教训 | 一句话 | 去哪读 |
