## 一、铁律一：静默失败 = 你的链子有问题，不是目标有问题

> **真实事故**：ROP 已生效（自证标记打出来了），但每次 `read(fd)` 都没有输出。连续 **60 次** fd 盲扫，每次都"成功但没数据"，于是结论写成"flag 不在这些 fd 上"。真相是：**rdx 被冻结成 `0x19`**，`read(fd, buf, 0x19)` 每次都从文件偏移 25 字节处读、读 25 字节就返回——flag 就在那个 fd 上，是我们自己没读到。

**判据固定成流程**：

1. **"没输出" ≠ "没数据"**。一个"成功但空"的返回，**第一嫌疑永远是调用者的参数错**。
2. **先自证链路，再怪环境**。发一个**自证 marker**（能证明控制流到达），再发一个**结果计数 marker**（能证明这次调用真的返回了、返回了什么）。**只有 marker 也打不出来，才允许怀疑目标。**
3. **同一个动作重复第 3 次就是错**：第 3 次前必须换一个"**能区分两种假设**"的实验，而不是换一个参数再试一遍。

**同一类事故的其它形态**（都是"我把读不到当成了不存在"）：

| 表现 | 真相 | 教训 |
|---|---|---|
| "fd 3/4 阻塞，flag 不在这些 fd" | flag 就在 fd 3；`rdx=SIZE_MAX` → `access_ok` 失败 → `-EFAULT`，零输出 | 静默失败先查参数 |
| "libc 的 read/write 能用" | 走 `__libc_single_threaded` 可取消慢路径，进程直接死 | 入口 `cmp byte [rip+0xef4b5],0` 没读对 |
| "openat 被 seccomp 杀了" | 没杀，是 `rdx` 被冻结成 `O_WRONLY` | 前两条造成的假象 |
| "base36/58/32 均乱码"（旧结论） | 新鲜重解就破了题 | 旧结论必须降级为候选假设 |
| RCE 链两次外带结果矛盾（`pos6 '['` vs `'g'`） | 靶机重启后 `__subclasses__()` 下标 **132→258 漂移**，旧链读错文件 | 动态索引每次连接前重扫 |

## 二、铁律二：结论必须记账（防"卡两天"）

### 2.1 机械化的防线：`tries.log`（照做，不要靠自觉）

在当前题目录维护一个 `tries.log`，每试一次**同一件事**就追加一行。**同一行内容第 3 次出现时，强制停下**，先回答三个问题再动手：

```
① 这次调用"返回值/errno"是什么？（没打印过就先去打印）
② 所有跟长度有关的参数（count/len/size/offset）实际值是多少？
③ 如果我的工具是坏的，现在这个结果会长什么样？——设计一个能区分这两种情况的实验
```

> 事故里，58 次 fd 盲扫中**没有一个文件打印过 read 的返回值**，所以"read 失败"和"read 成功但没数据"从来没被区分开。只要有这一道机械闸门，**19.8 分钟的空转会在第 3 次（约 1 分钟）就被拦下**。

### 2.2 做法规矩

- 每条结论后面挂 `[已验证|推测]` + **证据（命令/输出/文件:行）**。
- **矛盾即信号**：两次结果不一致、oracle 自相矛盾 → **立刻停手查工具/链路本身**。
- 接手任何"卡点清单"：**旧结论一律降级为候选假设**，第一动作是**重新读题面 + 附件原文**。
- 每写下一个"不可能"，问一句：**如果我的工具坏了，这个"不可能"会长什么样？**
- **不要用"我的工具没问题"当前提**——要把它当假设去验。

### 2.3 概率类判据：先算样本量再开跑

**稀有命中率实验样本必须够大**：真值 **0.39%**（2048 次实测 0.488% ≈ PKCS#7 的 1/256）的布尔 oracle，我先用 256 次得到 `0/256`，**差点否掉正确假设**。
→ 判据涉及概率时，先算"要多少样本才能区分假设"再开跑；**`0/N` 只有在 N 足够大时才是证据**。

### 2.4 布尔 oracle：用内容判据，不用长度判据

真事故：连续 2 小时用**响应长度**判真/假，实际判据是响应体末尾的 `success` 标记（长度差只是回显 SQL 位数差异）。
→ **盲注题先导出一对已知真/假响应做"内容"对照**；末字符探测全假 = 越界 = 字符串已结束（不补字符）。
→ 任何 oracle 先做**最小样本验证**（如 `7*7==49` 单请求），再用它当判据。

### 2.5 flag 台账：状态列只认平台回执

「已判正」只能由**平台回执**写入（`code:1 "恭喜，提交的Flag正确!"` 或 task 查询 `solved=true`）。
**会话自述、脚本自检、"六条判据全过"都不算状态**，最多写进备注列的 `[已验证]`。

- **把回执原文＋时间戳抄进总账那一行**（既防自己忘，也是裁判抽查的凭据）。
- 这条纪律是**双向**的：①「待提交」是活待办，截止前 20 分钟清点；②**"我以为没交"也必须先验证再动手**。
- 血亏实例：一题在 **09:44:24 就已被平台判正**（成交的是当日 **09:44:20 被拒后的第二个候选**），但总账、赛后复盘、运行时记忆**三层都记成了「待提交」**；于是第二天一整轮重解**推回了那个被平台拒绝的候选**并写进 WP。
  → **一条没人校验的台账 = 会自己繁殖的错误结论。**
- **赛后复解任何一题之前**：先在工作区会话日志里 grep 一次 `提交的Flag正确` / `提交的Flag错误` / `solved=true`，用回执把状态钉死，再决定要不要重推。

### 3.A 证据类：把推断当测量

| # | 错误模式 | 具体表现 | 对策 |
|---|---|---|---|
| 1 | 把"工具/链路失败"读成"目标不给" | 60 次 fd 盲扫、20 分钟 | 自证 marker + 结果计数 |

## 四、实战踩坑教训（对靶机/对二进制动手时的具体坑，12 条）

> **正典提示**：这些坑的**按题型版本在 `10-tech-index.md`**（Pwn / Web 各节，含同样的偏移与常量）。
> 本节保留"踩坑叙述"视角，便于按"我正在被什么咬"检索；**技术值有冲突以 `10` 为准，改值改 10**。

1. **输入载荷长度必须精确**：程序 read 固定字节（如 `0x98`/`0x9a`），发短了会吃后续输入造成**流错乱**，发长了**残留**。add/edit 的 payload 长度按反汇编/文档确定。
2. **`scanf %d` 的换行残留**：`sendline` 的 `\n` 会被 `scanf` 留下，后续 `read()` 会先吃掉它——**远程表现因实现而异，先小样本验证偏移再批量**。
3. **堆题先在本地复现再打远程**：Linux ELF 拷到 Kali/WSL；`LD_PRELOAD` 不可用就用系统 libc 验证布局/偏移；gdb 断点看真实 chunk 地址（**PIE 下用符号断点不用绝对地址**）。
4. **2 字节溢出落点**：edit 溢出写的是下一块 **size 字段低 2 字节**；改 size 要**保留 `prev_inuse` 位**（`0xa0`→`0x141` 而非 `0x140`）；改大 size 进 unsorted 时 **nextchunk 必须落在真实 chunk 上**（否则 invalid next size 崩溃）。
5. **泄露偏移校准**：`%lld` 打印的地址算 `libc_base` 后**必须验证页对齐**（`&0xFFF==0`），不对就调 bins 偏移（实战：`unsorted_head = __malloc_hook + 0x70`）。
6. **WAF**：平台 API 用脚本默认 UA 会被 **403**（返回 HTML 页），必须带**浏览器 UA + Referer**。
7. **诱饵 flag**：题内给的 flag 提交失败时，检查是否诱饵（信息可能在文件名/结构/描述里），**别死磕提交次数**。
8. **函数指针跨 4 字节字段拼接**：`+0x20` 的 **8 字节**指针被 `+0x20` 与 `+0x24` 两个 **4 字节**字段覆盖——低 4 字节来自字段 A、**高 4 字节来自字段 B**；改指针要**连高 4 字节一起控制（常须置 0）**，否则拼出 `0x00000001_xxxx` 之类非法地址崩溃。识别法：反汇编看到 `mov [x+0x20], edx`（4 字节写）而消费方 `call [x+0x20]`（8 字节读）就是此坑；gdb 断在 `call` 处打印 `CALL TARGET` 一眼定位。
9. **附件可能被平台 patch**：本地附件的 `FLAG="FAKE_FLAG"` 是**诱饵/占位**，部署版同一字段才是真值，且代码从不返回它——**只能 RCE 后读 class 文件**。**拿 flag 前在靶机侧核实。**
10. **ysoserial 兼容性**：Java 21 生成 CC payload 需 `--add-opens java.base/...=ALL-UNNAMED`；对靶机反序列化 **500** 时改用**靶机同款依赖 jar**（如靶机里的 `commons-collections-3.1.jar`）**自编 gadget 生成器**，本地编译即可，输出 base64 直发。
11. **PowerShell 二进制重定向会损坏数据**：`>` 会把 java stdout 按文本损坏 → 用 python `subprocess` capture **原始字节**；Windows Defender 会把"PS 调 java 生成 CC payload + webhook 外带"判为 Trojan（行为检测）——**改用 python 通道规避，勿在 PS 里堆这类命令**。
12. **Defender/杀软对本地工具误报**：`ysoserial-all.jar` 本身可能被标记，下载后如被杀**加排除或改用自编生成器**；**解题工具放工作区前先确认没被清理**。

## 五、把结论写下来的格式（复盘时用）

每条教训落盘必须是三行结构：**结论 + 证据 + 对策**。

- **结论**：一句话，可证伪。
- **证据**：命令/输出/文件:行/时间戳，能被人复核。
- **对策**：下次遇到时**具体做什么动作**（不是"要注意"）。

**没写下来的教训等于没发生。**
