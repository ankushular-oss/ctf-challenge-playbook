# 50 · 否证纪律与探针维度

> **何时读**：你正准备说「这不是答案」「这里没有」「此路不通」「数据是诱饵」的**任何一次**。
> 也用于开局定"我该用几种取法找"。
> **这篇不教知识，只教"什么时候允许下否证结论"。**

---

## 0. 为什么单独一篇

2026 羊城杯（TEAM），我三处否证全错，代价 3 道题：

| 我当时的结论 | 真实情况 | 我少做的那一问 |
|---|---|---|
| `encrypted_messages.db` 是诱饵，只有 4 条监控密文 | **row89 藏着碎片 3/5**（我只按 distinct 密文取了 4 条） | 去重前我数过全部行吗？ |
| 90+ 条路由扫完只有 4 个接口，没有梯度下载 | `GET /api/federation/log` 一直能下 300 个 `.npy` | 手写清单算"扫过"吗？ |

技术判断都没错，错的是**宣布否证的时机**。所以本篇只给四问与措辞三档。

## 1. 四问（按顺序，任一问答不上 → 不许写"不存在"）

### Q1 我用了几种取法？

不同对象，"取法"的定义不同：

| 对象 | 取法维度（至少两种才算"找过"） |
|---|---|
| 接口/路径 | 手写清单 ＜ 词表（SecLists / 内置 `common.txt`） ＜ **从前端 JS / 接口文档 / 响应里派生** |
| 隐写/编码 | 交错 vs 分平面、位序 MSB/LSB、通道顺序 RGB/BGR、字节对齐 0/1/2/3 |
| 日志/数据库 | 去重前 vs 去重后、前 N 条 vs 全量、单字段 vs 全字段（含 `deleted=1`） |
| 二进制字符串 | ascii / utf-16-le / utf-16-be / utf-32；`strings -n 4` 与 `-n 8` 各一遍 |

**措辞三档（写进记录，不许含糊）**：

- **不存在**：≥3 种取法都空，且写得出取法清单
- **未发现**：1–2 种取法空 ← 大多数情况只能写这个
- **未测**：0 种取法 ← 等于没查，不许进结论表

> 判据：`grep -c` 为 0 只证明"我这一种搜索没命中"，不证明"没有"。

### Q2 这是"数据没有"，还是"我的模型不匹配"？

模型错的典型症状：

- 候选命中**形状雷同**：全是 `pad=1`、`printable≈0.4`、全是同一个长度偏差 → 说明筛子只放行了同一类噪声，**不是真命中**。
- 统计量干净得可疑：全 0、全唯一、全等值、方差恰好相等 → 先怀疑自己取错了列/对齐错了。
- 所有候选都"差一点点"（4/5 位相同）：这是**模型差一个维度**，不是数据坏。

动作：**出现上述症状时，先换模型，不许宣布数据无内容。**

### Q3 判据只有一个 oracle 时，有没有交叉验证？

常见 oracle：`sha256` 目标值、AES/zip 的密码验证值（pv）、平台回执、单元测试。

- 单一 oracle 下穷举 = 拿全部算力赌一个假设；**至少两个独立 oracle 一致**才允许收工。
- 有 oracle 时优先用它**筛**而不是**证明**：先小集合验证 oracle 本身（自测一次已知明文往返），再放开搜索。

### Q4 题面点名的专有名词，搜过官方手册没有？

题面出现具体型号/格式/协议时，**第一动作是拿规格，不是造模型**：

| 例子 | 该去拿的东西 |
|---|---|
| "Correcting Selectric II" | IBM Selectric **Service Manual**（字符球排布表：4 tilt × 22 rotate） |
| `.E01` / EWF | EnCase/EWF 格式规范、sector size、chunk 表 |
| NexusFrame / 自定义二进制帧 | 抓一次真流量 + 帧头字段反推，别猜 |
| UE `FAES` / `Oodle` / IoStore `.utoc` | 引擎源码或公开实现（FAES = AES-256-ECB；IoStore 目录在压缩串表里） |

**"外部规则不可得"必须附检索式与失败记录**，否则它只是一个没做的动作。

## 2. 白给答案先验伪

- 服务端 debug 接口、注释里的 flag、README 的"提示串"：**全部当假设，复算一遍**。
- 羊城杯 NeuralVault 的 `/api/debug` 直接给 `suspected_clients:[2,6]` —— 真值是 `[3,7]`，是诱饵。
- 两类"明示诱饵"信号：① 自嘲/玩笑式提示（"这段字符串看起来像答案吗？"）② 与题面 hint 矛盾。

---

## 3. 中间产物 ≠ 答案

分片/碎片/字段拼出来的串，**默认是下一层容器的口令**，不是 flag：

```
拼接串 → 同目录的加密容器（*.dump / *.enc / *.zip / *.dat）
       → 用它当口令解容器
       → 明文里出现 flag 才是答案
```

代价实例：Lost_Memory 队友把 24 位拼装串当 flag 连交 **9 次全 `40001`**（每题 50 次额度），第 10 次才换方向当口令。

**提交前一句自问**：这个串是怎么被"生产"出来的？如果它是某次拼接/解密的输出，那它几乎一定是钥匙而不是锁。

---

## 4. 环境类"用不了"的判定

说"环境跑不起来"之前，分清三层，每层有独立探针：

| 层 | 探针 | 通过的样子 |
|---|---|---|
| 进程活着 | `/proc/<pid>/stat` 的 utime 增长、`dumpsys window` 里 resumed | utime 持续涨 |
| 出帧 | `dumpsys SurfaceFlinger --latency <layer>` | 有非 0 时间戳 |
| 输入进得去 | `input tap` 前后 `screencap` 的 md5 是否变化 | md5 变 |

结论必须写清**哪一层坏**（"不出帧"≠"进程死了"≠"点不动"）。羊城杯 千千的咲 就是"进程活、出帧 0、输入无效"三层三种原因叠加。

---

## 5. 服务端"不稳"的判定

- **挂住 ≠ 崩**：先 `curl --http1.0` 或加 `Connection: close` 复测一次；仍挂才叫不稳。
- 单线程服务被一个挂起的会话堵死时，**其它路由全部超时** —— 这是"被占满"，不是"路由不存在"。
  判据：换一个已知存在的路由（如 `/health`）一起打，它超时说明是被占满。

## 6. 外部取物：题面之外必须去拿的四类东西

> 羊城杯真正的分水岭不在"题难"，而在：**赢的题数据都在手上，输的题都要求去题面之外拿一样东西**。
> 同一场我拿下的 12082（AI 日志取证）是纯本地数据分析；输掉的四道全是"外部取物"没做。

| 类别 | 该去取的信号 | 动作 | 取不到时 |
|---|---|---|---|
| **手册/规格** | 题面点名具体型号、格式、协议、引擎模块 | 搜官方 Service Manual / RFC / 格式规范 / 引擎源码，关键词用**型号原文 + manual/spec** | 记录检索式与失败，改口"未取到"，不许写"不可解" |
| **可用接口** | 服务端返回"下载/日志/查询"类提示，或前端 JS 里有你没打过的路径 | 用词表扫一遍（SecLists），并从前端 JS / 响应头 / 报错里派生路径 | 记下"扫过哪些词表、多少条" |
| **可用环境** | 靶机在跑但"用不了"、模拟器不出画面、驱动/浏览器起不来 | 按 §4 三层拆开分别探针，确认坏在哪一层，再决定换环境还是绕开 | 写清"哪一层坏 + 换环境的具体条件" |
| **人眼确认** | 图像/贴图/截图/渲染结果"看起来没字" | 切区域放大 ≥5×、换通道、换对齐；贴到记录里留下截图 | 记"看过哪些区域、放大多少倍" |

**共同点**：这四类的失败在我这里都表现为"停手"，而不是"做错"。所以判据只有一条——
**卡住 15 分钟后，先问自己"我在等的是不是一样题面之外的东西？"** 是 → 立刻去取，或明确止损。

## 7. 判据钉死：新模型先验 oracle，再上量

数信杯能解 20/28，靠的是这条；羊城杯丢了它，代价是几万次无效搜索。

- **先用 20 次样本把响应语义钉死**（哪个字段是真信号、哪种回显是"已提交过"）。
- **先往返验证 oracle 本身**：已知明文加密回去是否吻合；`base32decode(b32encode(x)) == x`；
  `pbkdf2` 的 pv 用你自己造的 zip 验一次。
- **再上量**：模型验证过，穷举才有意义；模型没验证就穷举 = 拿算力赌一个未检验的假设。

反例（羊城杯 Jammed）：48 字符密码模型从未做过"正向构造 → 应命中"的自检，
就在 3.6M 数字置换、1.38M 双字符替换上反复跑，全空——**空得再多也不能证明模型对**。

## 8. 线索转换：题面里每句"氛围描述"都是一条约束

动作：把题面 / 接口返回 / hint 里所有**机制性句子**摘出来，逐条问「它在限制我的模型吗」。

羊城杯三处漏读（都不是算不出来，是没把话当约束）：

| 原文 | 它实际说的是 | 我当成了 |
|---|---|---|
| `/api/info` 的 `key_encoding: audit key 拆在两个恶意客户端的梯度矩阵里` | 存在一个**梯度矩阵数据源**；键 = 两个客户端 | 背景介绍，转去找 `/api/query` |
| 题面「外壳蚀刻的编号分段是为了读数方便，在固件里是连续编号」 | 芯片号要用**连续形** `YA20180507` | 无关细节（我按外壳形 `YA_20180507` 组） |
| 题面「时间与视角皆被抹去的四维星尘…寻回失落的共振时刻与交汇视线」 | 要指定 **t** 与 **相机视角** 才能成像 | 氛围文字，直接判"要跑 4DGS 网络" |

**规则**：出现「拆 / 分片 / 连续 / 抹去 / 某个时刻 / 某种视角 / 逐层 / 交叉 / 分段」这类词，一律先列成约束表再选模型。

**附带一条**：上一题否证过的通道（例如"LSB 无隐写"），**不能当下一题的前提**。羊城杯我把 skin secret 的平面 LSB 结论搬到 Lost_Memory，直接漏掉碎片 5/5。

## 9. 最小可判实验：先做「3 行代码能出结论」的那一步

定义：某个实验如果**能直接杀死你当前最强的假设**，就先做它，不管它多土。

- Jammed 反例：我先 OCR（1.5 h）→ 再穷举置换（3.6 M）→ 才想起"同一位置两页不同字"。
  正确顺序：把 A 页与 B 页**同序号、同字段**的字符按位置对齐 → 24×11 差异矩阵 →
  "某些列差异远多于其它列"一眼可见 → tilt/rotate 模型当天上午就能立起来，不必等手册也先能定性。
- 自检句式：**卡住 15 分钟时问「有没有一个 3 行代码的实验能直接推翻我现在的假设？」**

## 10. 收尾自检（写进 WP 的"死路表"之前）



- [ ] 每个否证都标了措辞档位（不存在 / 未发现 / 未测）
- [ ] 每个"没有 X"都写了取法清单
- [ ] 假阳性检查过形状
- [ ] 专有名词的官方资料检索式已记录
- [ ] 拼接串没有被直接当 flag 提交过

**这一步不必靠自觉**：`python <HARNESS_HOME>\tools\kcheck\kcheck.py --dir <任务根>\.kcheck gate`
会把上面五件事逐条变成 exit code —— 假设没测就被丢弃、结论没有已跑测试、
否定结论只依赖一种取法、题面线索没翻成约束、没记录权威时间源，任意一条不合规就 exit 1。
说"不成立 / 没有 / 是诱饵"之前先让 gate 归零（用法见 `tools\kcheck\README.md`）。
