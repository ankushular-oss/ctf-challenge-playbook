# 99 · 可复用亮点清单（从实战里沉淀出来的，**直接抄**）

> **何时读**：动手前扫一眼找现成招式；或在"这题像某种套路但想不起名字"时按关键词找。每条都是可以直接搬到当前题的打法或判据。
> 来源：`ctf-challenge-playbook` §六（可复用亮点，共 12 条，编号与原节一致，便于其它章节按"§六·N"引用）。

1. **本地 1:1 复刻靶机**：用附件自带的 `ld-linux` + `libc.so.6` 跑真二进制，
   自己写一个 `localserver.py`（真协议 + 真漏洞 + 把 `/flag` 放到指定 fd）。
   → 线下无限次调试，线上只跑一次。**这是把"远程试错"变成"本地确定"的关键。**

2. **自证 marker 分层**：每完成一个原语就打一个唯一 marker（`XXX-STAGE-OK-<rand>`），
   把"哪一层生效了"变成可读输出。

3. **出题人后门法**：二进制里**没有被任何代码引用**的函数/常量常常就是干净的后门
   （长城杯 `0x2ae0` 是未被引用的 `fopen("/flag")`）。
   搜法：xref 为空的函数、只被数据引用的地址、`.rodata` 里没被引用的常量块。

4. **DNS TXT 当校验和**：抓包里的 DNS TXT 常宣告附件 sha256，
   用它验证"我解出来的固件是不是原件"（长城杯靠它确认解密正确）。

5. **弱 DH**：模数只有 **48 bit**（自称 "dev modulus"）→ 离散对数秒解；
   看到"小模数/小指数/dev"字样先算位数。

6. **不受信任的队友资料要复核**：队友给的 `1(1).txt` 有错值/不存在的附件清单，
   照抄会带偏（错误 K 值、"置换表"其实是 SSE `pshufb` 掩码）。
   **交叉验证，别把别人的结论当事实。**

7. **交互题先做"参数敏感性矩阵"**（极氪《Diag Shellbox》教训，本清单最重要的一条）：
   面对一个"门/判定/校验"接口，先拿 3 个差异极大的参数各打一次，比较**回显是否变化**。
   若回显与参数**完全无关**（本例 `0x21` 喂了 ~5900 组参数与序列，回显恒为 `02 74 6c 76`），
   那就得到了本题最强的一条事实：**门不是靠参数开的** → 立刻停止参数枚举，转向
   调用次数 / 调用顺序 / 时序驻留 / 帧长 / 另一条入口。**"回显对输入不敏感"是结论，不是噪声。**

8. **协议题先定帧格式，再谈语义**：先用"长度不匹配"实验（声明长度 ≠ 实发字节数）判定
   首字段到底是长度还是别的字段——本例声明 1 实发 2 字节时，服务端只吃掉 1 字节并把
   余下字节当成下一帧的长度，一次实验就锁定 `u32 大端长度`；此前所有 ASCII 探测失败，
   根因都是首 4 字节被当成长度（`help\n` → `0x68656c70`）。

9. **工具先离线验收，再上真机**：凡是要跑在"窗口只有几十秒"的靶机上的脚本，先对**本地 mock**
   跑通。本例 MT19937 状态恢复用本地 `random.randbytes` 自测，一次抓出两个 bug
   （untemper 写错、重建状态后忘了快进已观测的 96 个字）。离线自测的收益＝省下一整轮。

10. **可观测量的取值范围先枚举出来**：本例只有两个状态名（`cold`/`tlv`）、`0x33` 恒 `locked`、
    五个固定回显体。把"可观测量的全部取值"写成一张表，再用它反推"还剩哪些自由度"，
    比继续加假设族快得多。

11. **哈希/编码口径先用"已判正的题"验一遍**（极氪 390 教训）：
    凡题目要求 `sha256(...)` 之类，先在同赛**已判正**的题上复算，把口径钉死再开始推导——
    极氪 390 上，正是用已判正的 389 复算出 `sha256("<答案大写 hex 文本>")` 的前 16 位/后 16 位
    与平台答案完全一致，才确定"**哈希输入取答案的大写 hex 文本，而非原始字节**"，
    这一步直接解释了为什么此前 6 条候选必错。**同赛同模板的题，约定是共享资产。**

12. **"极简二进制协议"题：预言机语义用统计量钉死，不要去扫密钥空间**
    （极氪 397 OTA Shadow Oracle，平台 `solved_count=0`，**8192 次查询零爆破**拿下）：

    ① **分帧靠判决性实验**——"声明长度 ≠ 实发字节数"区分长度字段；改 payload 第 2 字节响应不变
       ⇒ opcode 只在首字节；二分长度得上限；空转 **95 s** 无数据 ⇒ 无 banner、无空闲超时；
       `length=0` 直接断开 ⇒ **协议违规行为也是规格的一部分**。
    ② **对"总能返回数据"的那个 opcode，先证伪弱随机**：取 **624 个 32 位字** untemper + twist，
       预测后续全不中 ⇒ 不是 MT19937 ⇒ 果断换方向（本例是 48 B token）。
    ③ **布尔预言机的语义靠命中率判定**：随机 32 B 打 **2048 次**命中 **0.488% ≈ PKCS#7 的 1/256**
       ⇒ 一次锁定"这是 padding oracle"。**稀有命中率实验样本必须够大**——先用 256 次得到 `0/256`，
       差点否掉正确假设。
    ④ 再用两把尺子定形状：**逐字节扫描**（每位置试 256 个取值）定出 padding 长度 = **4**；
       **截断实验**（`C1|C2` 合法 / `C0|C1` 非法 / 单块非法）定出"只校验末块明文"。
    ⑤ 拿到 oracle 走标准链：逐块还原 `D(block)` → 解出明文（本例 `role=user  sid=<8hex>`）
       → 用 **CBC 可延展性只改 IV** 伪造 `role=admin` → flag。

    → **反例警示**：本题曾在 `0x03` 的"密钥空间"上发了约 **7000 万次**请求（3 字节全扫、
      4 字节 alnum/printable、字典、magic 常量），**全部是弯路**——真相在**另一个 opcode 的语义**里。

13. **产物自证 + 二阶注入**（羊城杯 pdfchallenge，md2pdf / Firefox print-to-pdf；我在这题上判错过两次）
    ① **先读产物自己的 metadata**：PDF 的 `Creator: Mozilla Firefox 153.5.1` / `Producer: cairo 1.18.4`
       ⇒ 渲染链是 **Firefox headless print-to-pdf**，不是 Puppeteer。一个字段就换掉了整个假设空间
       （Chrome 下 JS-off 意味着没原语；Firefox 下 iframe 内容会被**打印进 PDF**）。
    ② **用相对链接问出绝对路径**：提交 `[a](t)` 与 `[b](#frag)`，再读 PDF 的 **Link Annotation** →
       `file:///tmp/renders/t`、`file:///tmp/renders/<rand>#frag` ⇒ 一次拿到 base 目录、临时文件名、
       以及"`/path` 会解析成 `file:///path`"这条权限事实。
    ③ **注入点分两类**：用户写的 HTML（**被转义**，`<iframe>` 出字面量）≠ 安全；
       真正能用的是**渲染器自己拼出来的属性** —— fenced code 的 language info string 直接进 `class="…"`，
       **双引号未转义**：``` ```js"><iframe src="/flag"></iframe><code class="x ``` ⇒ 闭合属性、注入标签。
    ④ **判"渲染 vs 转义"要找本应消失的字符**：我当初用"文本里出现了 HELLOXYZ"当渲染证据，
       正确判据是"文本里有没有 `<h1>` 字面量"。一字之差，结论反了，直接导致放弃。
    ⑤ **先证通用再取答案**：同法读 `/etc/passwd` 证明任意文件读取，再读 `/flag` 与 `/proc/self/cwd/flag`。
    ⑥ 失败归因要落到层：`<iframe>` 不生效可能是被转义 / 被 CSP 拦 / 被 sanitizer 删——三层处置完全不同，
       不能由一次失败推出"这种标签不能用"。
