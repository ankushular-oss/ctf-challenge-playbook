> **何时读**：开赛前定分工与预算时；准备派子 agent、开新会话、开动态靶机之前；以及发现响应变慢、

## 〇、结论先行（只要记住这 7 条）

1. **花费 ≈ 上下文体积 × 步数**。多开一个会话不是线性加钱，是**每一项都乘一个 10 万～28 万的常数**。
2. **实测**：一场 2.5 小时的比赛烧掉 **67 个会话 / 10.6 亿 token（90% 是 cacheRead）**，
   **开赛 14 分钟主控会话就停了**，两道 500 分动态题全程没打上。这不是"多花了点钱"，是**直接输掉比赛**。
3. **三条线就够了**：主线（自己解）+ 子 agent 线（跨模型交叉验证卡点）+ 资源线（长任务后台 job）。
4. **硬上限写死**：顶层 ≤ 4、子会话 ≤ 8；**子会话只给一张任务卡**（题号/路径/flag 格式/停止条件），
   绝不塞 skill 全文、notes、flags.md。
5. **停止信号 = 收口信号**，不是"再试一次"信号。延迟飙升 / 连续 TRANSPORT / 子会话被自动 stop → 立刻收口。
6. **同一题只允许一条活跃专线**（题目级入场闸门）；进题前先看台账与题目录，已有解法就交叉验证、**不重推**。
7. **人是唯一稳定的调度者**：主控停摆必须有替补约定，否则整场变孤儿。

## 一、三条线（§3.1）

| 线 | 做什么 | 硬要求 |
|---|---|---|
| **主线** | 自己解当前题 | 每一轮都要产出"缩小假设空间的事实"，不是"又多一个脚本" |
| **子 agent 线** | **跨模型交叉验证卡点** | **fresh spawn**；产物必须落盘到**绝对路径** |
| **资源线** | 长任务（爆破/扫描/外带/开靶机）走**后台 job + 逐进度日志** | **断点可续**，中断后能接着跑 |

**接题即并行双线**（自己主线 + 派一条子 agent），不要等卡住才想起来派。

## 二、子 agent 任务卡（★"只给路径、不塞 skill 全文"）

**完整模板（照抄，一题一张卡）**：

```
【任务卡】<题号> <题名>
附件绝对路径：<绝对路径>
题面要点：<1–3 行，逐字抄题面里的关键信息（flag 格式 / 已知输入输出 / 规则）>
flag 格式：<题面原文写法，如 GEELY{...} 或 <hash前16>_<hash后16>>
已确认事实（勿重做）：<...>
已验证错误（勿重试）：<...>
疑点清单：<...>
最小验证步骤：<一条能区分两种假设的实验>
产物落盘：<绝对路径>  ＋  "不要提交平台"
停止条件：默认不停；但①同一方向第 3 次不成功 ②需要人操作（GUI/账号/短命令）
          ③要提交不确定的 flag —— 立刻停下来报告，不要继续硬啃。
交接：每完成一个阶段就更新 chals/<题号>/HANDOFF.md（已确认事实 / 已证伪 / 最小下一步）。
细节按需读 chals/<题号>/HANDOFF.md，不要读全库。
```

配套三条纪律：

| # | 纪律 | 证据（真事故） |
|---|---|---|
| 1 | **只给一张任务卡**，宁可少给。skill 主控读一次，只把**相关的 3–5 条**抄进任务卡 | 每个子会话 prompt 里都塞了约 **20 KB 的 skill 正文**，子会话第一件事又把同一个 skill 读了一遍——这笔钱要**乘它的步数**付 |
| 2 | **绝不**把整份 skill / 整份 notes / 整份 `flags.md` 转发进每个子会话 | 同上：那是"每个子会话的入场费 × 它的每一步" |
| 3 | 任务卡里**写死 handoff 义务**（每阶段更新 `HANDOFF.md`：已确认 / 已证伪 / 最小下一步） | 被停的会话**最后一条事件都是 `tool/call`**，没留下一句"我做到哪"，接手者只能从产物反推，白烧一轮 |

> **配套：交接提示词里必须写"停"的条件。** 曾用过"全程自动化：不要中途停下来问我确认"的模板，
> 结果 Agent 在错误方向上持续规模化，逼得用户亲自打断（原话：**"你给我指令我自己运行"**、
> **"？你能不能先给我运行 ORW 的指令再去继续？？？"**）。
> 正确写法：**"默认不停；但同一方向第 3 次不成功、或需要人操作时，立刻停下来报告。"**

## 三、人机分工（规则允许 AI 时，§3.2）

- **短命令，让用户自己跑**：需要 GUI（IDA / x64dbg）、需要用户账号、或只是几条命令时，
  直接把**可复制的一条命令**给用户——别自己去点，别让用户干等。
- 需要人决策 / 人操作时**立即给指令**，不要"我先把这条线跑完再说"。
- **用户给你的每一次催促，都是在说"你的循环太长了"** → 缩短单次往返。
- 不要自己代持凭据。
- 反向约束：并发与交互也吃预算——**正赛期间能全自动就全自动**（省掉人机往返的步数），
  但**永远保留"需要人操作就立刻给指令"这条通道**。

## 四、上下文纪律（§3.3）

| # | 纪律 | 说明 |
|---|---|---|
| 1 | **正赛开全新会话** | 测试赛/准备期的上下文用**交接文档**转移，绝不带进正赛；不要复制上下文 |
| 2 | **子 agent 一律 fresh spawn** | fork 长历史会话当顾问 = 让 pro 模型重读几天历史；反证：一个全新子 agent 11 分钟解出题 |
| 3 | 开赛前**验证子 agent 能读到 skill** | 慢会话下子 agent 的 skills 目录可能是空的 |
| 4 | **每 30 分钟测一次响应延迟** | >20 s/轮就压缩上下文或换会话续战（**进度必须已落盘**） |
| 5 | **单个巨型工具输出（>100 KB）先落盘再摘要** | 别让它进上下文 |
| 6 | 不清理的巨型会话会让每轮推理又慢又贵 | 尸检：**94.5 小时不清理**的会话 → 赛段 flash prompt tokens **1.52 亿**、用户报"太卡"、子 agent 罢工、**18 分钟空窗** |

## 五、资源 / 预算治理（§3.4 ＋ §7.12 合并）★ 本文件最重要的一节

### 5.1 实测账单（2026-09-19 极氪赛，2.5 小时）

| 项 | 数值 |
|---|---|
| 会话数 | **16 个顶层 + 51 个子会话 = 67 个** |
| 总 token | **1,065,326,473**（未命中输入 97.7 M ＋ 输出 7.8 M ＋ **缓存读 959.9 M ＝ 90%**） |
| 单会话最高 | **76.4 M**（398 专线：5.55 M 未命中 ＋ 70.9 M 缓存读 / 247 步） |
| **单步实测** | **产出 349 token 的一步，重读了 184,448 token 上下文（比值 528:1）** |
| 派线动作 | **09:36–09:38 一口气派 15 条题目专线 ＋ 另 15 个顶层会话** —— 这张账单的直接来源 |
| 另一份尸检 | 一个 **94.5 小时不清理**的巨型会话：每轮又慢又贵、子 agent 罢工、18 分钟空窗 |

**⇒ 花费 ≈ 上下文体积 × 步数。多开一个会话不是线性加钱，是每一项都乘一个 10 万～28 万的常数。**

### 5.2 两条集体中断时间线（后果不是"多花钱"，是丢分）

```
2026-09-19 09:30  开赛
2026-09-19 09:36–09:38  一口气派 15 条题目专线 + 另 15 个顶层会话   ← 账单源头
2026-09-19 09:44  ①主控会话停了（调度台消失、15 条专线变孤儿）
                 ②三个停止信号同时出现：响应延迟 >20s ＋ 连续 TRANSPORT 失败 ＋ 子会话被运行时自动 stop
                 ⇒ 开赛后 14 分钟，整场事实上失去调度
2026-09-20 11:22–11:30  全部仍在跑的会话被同一波掐断（8 分钟窗口内集体中断）
结果：两道 500 分动态题（398 / 399）全程没打上
```

### 5.3 机械化防线（照做，不要靠自觉）

1. **赛前写死预算**：本场 token 上限 ＋ 每会话上限 ＋ 子会话上限，写进工作区 `README.md`。
2. **并发上限：顶层 ≤ 4，子会话 ≤ 8**。短赛制用不到几十个会话；
   多出来的会话不是多线作战，是**互相重读同一份上下文**。
3. **每 30 分钟查一次各会话 tokenUsage**（会话列表自带），任一超标 → 立即停派新会话并收口在跑的。
   （把这条巡检也挂进计时器。）
4. **子会话 prompt 只给一张任务卡**：题号 / 题名 / 附件绝对路径 / flag 格式 / 停止条件
   ＋ 一句"细节按需读 `chals/<题>/HANDOFF.md`"。（模板与证据见上面第二节。）
5. **每个子会话任务卡里写死**："每完成一个阶段就更新 `chals/<题>/HANDOFF.md`
   （已确认事实 / 已证伪 / 最小下一步）"——**防断线无交接**。
6. **停止信号 = 收口信号，不是"再试一次"信号**：出现 ①响应延迟 >20 s ②连续 `TRANSPORT`/额度类失败
   ③子会话被运行时自动 stop —— 立刻要回在跑会话的结论、写 handoff、**停止加派**。
7. **调度会话必须有替补约定**：主控超过 10 分钟无新事件，在跑的会话应主动落盘并回报用户。
   **人是唯一稳定的调度者。**
8. **题目级入场闸门**：同一题只允许**一条活跃专线**。进题前先看 `flags.md` 该题状态 ＋ `ls chals/<题号>/`；
   已有解法就做**交叉验证**，**不重推**（真事故：同一题最多被 **3 条路径**重推）。
9. **动态靶机另立"配额线"**（见 5.4）。

### 5.4 动态靶机配额线（本赛最痛的战术损失）

| 要点 | 内容 |
|---|---|
| 赛前 | **确认每账号能开几个场景**（平台有"已创建最大场景数"限制） |
| 取到靶机立刻登记 | `IP:PORT / 题号 / 谁在用 / 何时释放` |
| 运行中 | **同一时刻只开一个，用完立刻 destroy，手上永远留一个空槽** |
| 真事故 | 一台靶机占着**唯一槽位** ⇒ 398 / 399 两道 **500 分**题**建不出来**，全程没打上 |

### 5.5 账单与时间线怎么量出来的（可复核）

数字来自**解压 DSH 会话原始日志逐事件统计**（不是回忆、不是估算）：
`<HARNESS_HOME>\sessions\<workspace>\<sid>\session.v3.jsonl.zstd`。
会话原始日志是本场**唯一可信的"事实基线"**——同时给出 ①每个会话真实起止时间 ②每步 token 用量
③平台回执原文。现成脚本与用法见 `30-local-toolchain.md`（会话日志取证一节）；
用它做"复解前状态钉死"的用法见 `04-flag-and-ledger.md`。

## 六、协作 / 交付纪律（§7.5，血亏换来的）

| # | 纪律 | 证据与正确动作 |
|---|---|---|
| 1 | **不要用 Office COM 做"渲染验证"** | `Word.Application` ＋ `ExportAsFixedFormat` 导 PDF 验版式 → **120 s 超时被中断**，还留下**分不清归属的 `WINWORD` 进程**（事后系统里 3 个）。格式正确性改用**程序化自检**（包部件逐字节比对 ＋ 样式签名包含关系），不引入"会卡住、会留残留、会误伤用户 GUI"的重家伙 |
| 2 | **残留进程可以精确认领，不必"只能放着"** | `Get-Process WINWORD \| Where-Object { [string]::IsNullOrEmpty($_.MainWindowTitle) }` 与用户自己开着的 Word（有标题栏，如 `TEAM-WP.docx - Word`）区分开 → `Stop-Process -Id <PID>` **按 PID 结束**。认领依据 = **无窗口标题 ＋ 启动时间**；**绝不按进程名批量杀** |
| 3 | **用户说"不用截图 / 不用验证" = 立刻停链路** | "不用了"本身就是撤回指令，不是背景信息。真犯过：被叫停后还在调控制台字号、准备自己起终端窗口，白耗好几轮 |
| 4 | **skill 里的硬参数会过期** | 曾按 skill 记的版式（微软雅黑 / Times New Roman / 6.74 in 图）去对参考件，而参考件实际是 pandoc 风格、无图、GeistSans——**完全不是一回事，照抄会整体错版**。凡"对齐某个参考件/模板"的任务：**先解包量一遍再动手** |
| 5 | **交付前自检写成"包含关系"，不是"看着像"** | 输出里出现的**每一个样式签名**都必须在参考件里已存在；多出来一个 = 你自己造了样式 |
| 6 | **别把参考件里明显的 bug 一起克隆** | 参考件有一处把两行代码挤进同一个 run、没换行；按参考其余同类段落的正常做法写 |

> 第 1/2/3 条是**协作层**的纪律（对任何"重家伙"都成立）；第 4/5/6 条在 WP 交付上的完整实现
> （版式侦测脚本、原型克隆、逐段签名比对）见 `05-wp-delivery.md`。
